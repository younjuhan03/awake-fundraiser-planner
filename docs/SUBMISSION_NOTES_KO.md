# MSBAi 제출용 검토와 수정 내역

## 평가

강점은 실제 운영한 조직의 문제를 가지고 불완전한 기록을 검토한 뒤 실행 가능한 판단 기준을 만든다는 점이다. 기술적 복잡성보다 **문제 정의·데이터 판단·의사결정·검증 계획**을 보여주는 사례로 활용하면 설득력이 높다.

수정 전에는 분석 숫자가 먼저 보이고 본인 역할과 핵심 판단이 흩어져 있었다. 단순 계산값이 ‘추천 생산량’으로 표시되고 실증 근거 없는 50% 판매율에 ‘expected’라는 표현이 사용된 점도 수정했다.

| 항목 | 반영한 수정 |
|---|---|
| 첫 화면 | 영문 `index.html` 추가: 문제·역할·판단·계산기·증거·한계 순서 |
| Streamlit | Project Overview를 기본 화면으로 추가, 기존 분석 탭 유지 |
| 생산량 표현 | ‘추천’ 대신 ‘선택한 여유분에 따른 생산량’ |
| 경제성 | 사전주문만 생산하는 경우 대비 추가 순이익과 약 50.3% 손익분기 판매율 |
| 시나리오 | 0%·사용자 선택·100%로 표현. 기대값이나 예측처럼 보이지 않게 수정 |
| 가정 분류 | 역사적 원가 계산은 derived, 다른 행사에 적용하는 원가는 assumed |
| 성과 구분 | 운영 방식의 지속 사용과 새 도구의 도입·효과를 구분. 실증되지 않은 순이익·폐기율 개선을 주장하지 않음 |
| 검증 | NaN·무한대·가격 조회의 소수 수량 거부, 회귀 테스트 추가 |
| 문서 | README, 영문 사례, 한국어 리더 요약, 실행 방법 정리. 깨진 안내 문구 수정 |
| 패키지 | 원본 CSV·SQL·소스와 계산 구조 보존. 캐시와 이전 화면 캡처 제외 |

## 제출 전 남은 확인

1. **역할·시기:** 원본의 Finance/Social Leader를 유지하되 확인되지 않은 재임 시기는 강조하지 않았다. 이력서·추천서와 맞추고, 담당하지 않은 F24/S25 행사 수익을 본인 성과로 쓰지 않는다.
2. **실제 사용:** 사전주문 운영 경험과 앱 도입은 별개다. 앱·Excel이 실제 전달·사용되었다는 확인이 없어서 도입 성과로 쓰지 않았다.
3. **본인 기여:** AI 코딩 도움을 명시했다. 직접 정의한 문제·검토한 장부·이해하고 검증한 계산을 설명할 수 있어야 한다. 코드 전체를 독립 구현했다고 주장하지 않는다.
4. **원천 대조:** ZIP에 원본 장부·주문 화면이 없어 CSV 각 행을 독립 대조하지 못했다. 기존 불일치는 보존했다.
5. **공개 범위:** 표시 페이지는 집계값만 사용한다. 원본 주문 CSV에는 가명 ID와 타임스탬프가 있으므로 저장소 전체 공개는 별도로 판단한다.
6. **접속 주소:** 압축을 풀고 `index.html`을 연다. 심사자에게는 외부에서 열리는 주소가 필요하다. 이 패키지 전달로 공개 게시가 완료된 것은 아니다.

## 포트폴리오 활용

제목 예시: **AWAKE Fundraiser Planner — Production Decisions under Uncertainty**. ‘실제 조직 기록을 대조하고 가정에 따른 추가 생산의 손익분기 기준을 제시한 도구’에 초점을 둔다. 머신러닝이나 복잡한 최적화를 추가하지 않은 점은 이 자료에서 약점이 아니다. 후속 가치는 실제 행사 데이터를 수집하고 의사결정을 검증하는 데 있다.
